## Edit and regenerate help

Install development tools separately from runtime dependencies:

```r
install.packages(c("roxygen2", "pkgload"))
roxygen2::roxygenise(".")
```

Run this from the checkout root. roxygen2 may load or compile the package while generating documentation. Roxygen markdown is enabled in `DESCRIPTION`. Review generated changes to `man/` and `NAMESPACE` together with the corresponding `R/` comments.

`R/RcppExports.R` and `src/RcppExports.cpp` are generated by `Rcpp::compileAttributes()`. Regenerate them only if the native interfaces change. The low-level exported `SurvPT()` wrapper has a dedicated help source in `R/native-interface.R`; most users should call `survPT()`.

## Build and check

From the directory containing the checkout, run:

```sh
R CMD build --no-build-vignettes --no-manual SurvPT
R CMD check --no-manual --no-build-vignettes SurvPT_0.2.0.tar.gz
```

Inspect `SurvPT.Rcheck/00check.log` and the test output under `SurvPT.Rcheck/tests/`. These commands omit PDF manual generation and vignette building; they do not imply that a PDF manual has been checked. Roxygen examples and package tests are still run.

On Windows, long paths inside `.git` can prevent `R CMD build` from copying a checkout before exclusions are applied. In that case, create a short-path staging directory containing `DESCRIPTION`, `NAMESPACE`, `LICENSE`, `NEWS`, `README.md`, `CONTRIBUTING.md`, `CITATION.cff`, `.Rbuildignore`, and the `R/`, `man/`, `src/`, `tests/`, `inst/`, `Examples/`, and `docs/` directories. Copy C++ sources and makefiles, not compiled objects. Build from that directory and compare the archive's source files with the checkout. Guides are retained in the source archive for readers downloading that artifact; installed R help is generated separately from `man/`.

Do not reuse a stale DLL as evidence that a modified source package works. Install the newly built archive into an isolated library and run checks against that installation. `R CMD INSTALL --preclean` forces compilation of the package sources.

## Regression coverage

`tests/pt-conditional-base.R` checks 12 mixed-censoring configurations: three PT bases, two support types, and two depth limits. It independently reconstructs two allocation steps, checks output probabilities and densities, verifies parent/child conservation, integrates density, and checks finite and infinite tails. It also checks three root-only and three exact-data configurations. The regression detects the allocation inconsistency in version 0.1.0.

Run it against an installed package with:

```sh
Rscript tests/pt-conditional-base.R
Rscript Examples/quickstart.R
```

Verify `find.package("SurvPT")` if multiple libraries or checkout-loaded namespaces exist. Legacy large simulations are not part of the regression suite, and passing PT tests is not validation of every OPT or fiducial procedure.

## Check findings and portability

The package's current makefiles add `-O0 -g`, use GNU make syntax, and use R's OpenMP, BLAS, and LAPACK flags. Existing native code writes progress through `std::cout`. These can produce package-check warnings or notes; document them instead of describing a warning-bearing check as clean. Changing those settings is a separate compiler/portability task.

Historical example filenames or dependencies can also appear in check output. Keeping repository guides and citation metadata in the source archive can produce a note about nonstandard top-level files. No license grant has been selected; the `License: file LICENSE` field points to a permission-status notice, not an open-source license.

## Prepare a private release

Update `DESCRIPTION`, `NEWS`, `CITATION.cff`, and the software entry in `inst/CITATION` together when changing the version. Rebuild after final documentation edits, rerun the examples and relevant tests, and inspect the archive for unintended files. Build-time metadata in `DESCRIPTION` and normalized line endings are expected differences; source behavior should match the checkout.

Record the archive checksum, source commit, R/toolchain versions, check results, and any unresolved warnings. Distribution is through the maintainer's authorized private channels. Building a package does not require a public GitHub release, GitHub Pages, or a visibility change.
